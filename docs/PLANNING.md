# 문서 스캔 앱 기획서 (가칭: 심플스캔)

> CamScanner류 문서 스캔 앱의 핵심 기능을 참고하되, 브랜드·코드는 독자적으로 새로 설계한 웹 앱(PWA) 기획서입니다.
> 앱 이름은 상표 문제로 "CamScanner"를 그대로 쓸 수 없어 가칭을 사용합니다. (11장 참고)

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 스마트폰/PC 카메라로 문서를 촬영해 자동 보정 후 PDF·이미지로 저장·공유하는 웹 앱 |
| 플랫폼 | 웹 앱(PWA) 우선 — 현재 리포지토리의 Next.js 세팅 기반 |
| 1차 목표 | 로그인 없이 브라우저에서 바로 스캔·저장·내보내기까지 되는 MVP |
| 확장 방향 | OCR, 클라우드 동기화, 모바일 앱 패키징 |

## 2. 타겟 사용자

- 계약서·영수증·명함·학습 자료 등을 자주 스캔해서 PDF로 보관하는 직장인/학생
- 스캐너 없이 스마트폰만으로 빠르게 문서를 디지털화하고 싶은 일반 사용자
- 간단한 조작(촬영 3초, 저장 1탭)을 원하는, 앱 사용에 익숙하지 않은 사용자도 포함

## 3. 디자인 원칙 — "간편하고 눈이 편한 UI"

요청하신 두 가지 기준(간편함, 눈의 편안함)을 아래 구체적 규칙으로 정리했습니다.

- **화면당 핵심 동작 1개**: 각 화면은 주요 액션 버튼 하나를 중심에 두고, 부가 기능은 아이콘으로 축소
- **눈이 편한 색상**: 순백(#FFFFFF)·순검정(#000000) 대비 대신 부드러운 톤 사용
  - 배경: `#F7F7F5`(라이트) / `#15171A`(다크)
  - 텍스트: `#1F2328`(라이트) / `#E7E7E5`(다크) — 대비는 유지하되 눈부심 방지
  - 포인트 컬러 1개만 사용(예: 세이지 그린 `#4C8C6B` 또는 소프트 블루 `#3B7DD8`), 나머지는 무채색
- **다크모드 기본 지원**: 시스템 설정 자동 감지 + 수동 전환, 야간 촬영 시 눈부심 최소화
- **큰 터치 영역**: 촬영·저장 등 핵심 버튼은 최소 48×48px, 손가락 오조작 방지
- **여백 중심 레이아웃**: 카드·리스트 사이 충분한 padding, 한 화면에 정보 과밀 금지
- **아이콘 + 짧은 텍스트 라벨 병행**: 별도 학습 없이 직관적으로 이해 가능하도록
- **절제된 애니메이션**: 전환 150~200ms 이내, 과도한 모션·효과 지양
- **일관된 타이포 스케일**: 12/14/16/20/24px 정도로 제한, 시스템 폰트 사용(로딩 지연 없음)

## 4. 핵심 기능 (MVP)

1. **문서함(홈)** — 스캔 문서 목록을 썸네일 그리드/리스트로 표시, 최근순 정렬
2. **스캔(촬영)** — 카메라 접근(getUserMedia), 문서 경계 가이드라인 표시, 촬영 또는 갤러리에서 이미지 선택
3. **자동 보정** — 문서 테두리 자동 감지 + 4점 수동 조정, 원근 보정(warp)으로 반듯하게 펴기
4. **필터** — 원본 / 흑백 / 그레이스케일 / 고대비 문서 모드
5. **다중 페이지 관리** — 한 문서 안에서 페이지 추가·삭제·순서 변경
6. **내보내기/공유** — 여러 페이지를 하나의 PDF로 생성, 이미지(JPG/PNG) 내보내기, Web Share API로 공유
7. **로컬 저장** — IndexedDB 기반 오프라인 저장, 로그인 없이 전체 기능 사용 가능

## 5. 확장 기능 (차후 버전)

- OCR 텍스트 인식 및 텍스트 복사/검색 (Tesseract.js, 한국어 우선)
- 로그인 + 클라우드 동기화로 멀티 디바이스 지원
- 폴더/태그로 문서 정리, 검색
- 워터마크·서명 추가
- 다국어 UI 지원

## 6. 정보 구조 (화면 목록)

- 홈(문서함)
- 촬영 화면
- 편집 화면(크롭 · 보정 · 필터)
- 문서 상세(페이지 리스트, 순서 변경)
- 내보내기/공유 시트
- 설정(다크모드, 기본 저장 형식 등)

## 7. 주요 사용자 플로우

1. 홈에서 `+` 버튼 탭 → 촬영 화면 진입
2. 문서 촬영(또는 갤러리에서 이미지 선택)
3. 자동 감지된 경계 확인 · 필요 시 4점 조정 → 확인
4. 필터 선택 → 페이지 추가 촬영 여부 선택
5. 문서 이름 입력 후 저장 → 문서함에 표시
6. 문서 상세에서 PDF로 내보내기 또는 바로 공유

## 8. 기술 스택 (제안)

| 영역 | 기술 |
|---|---|
| 프레임워크 | Next.js + TypeScript + Tailwind CSS (현재 리포 세팅 기반) |
| 카메라/이미지 처리 | WebRTC(getUserMedia) + Canvas, 엣지 감지·원근 보정은 OpenCV.js |
| PDF 생성 | pdf-lib (클라이언트 사이드) |
| 로컬 저장 | IndexedDB (idb 라이브러리) |
| PWA | next-pwa 또는 Service Worker 직접 구현 — 오프라인 지원, 홈 화면 추가 |
| (차후) OCR | Tesseract.js |
| (차후) 백엔드/인증 | Supabase (Auth + Storage + DB) |

## 9. 비기능 요구사항

- **성능**: 이미지 처리 500ms 이내 반응, 대용량 이미지는 다운스케일 후 처리
- **반응형**: 모바일 우선 설계, 태블릿·데스크톱도 대응
- **오프라인**: 인터넷 연결 없이도 촬영·저장·PDF 생성 가능
- **브라우저 호환성**: 최신 Chrome, Safari(iOS 포함) 우선 지원
- **개인정보**: MVP는 서버 업로드 없이 로컬(브라우저) 처리, 클라우드 저장은 이후 옵트인 기능으로 추가

## 10. 개발 로드맵

- **Phase 1 (MVP)**: 촬영 · 크롭/보정 · 필터 · PDF 내보내기 · 로컬 저장 · 반응형 UI
- **Phase 2**: OCR, 문서 검색, 태그/폴더 정리
- **Phase 3**: 로그인 + 클라우드 동기화(Supabase), 멀티 디바이스
- **Phase 4**: 모바일 앱 패키징(Capacitor) 또는 네이티브 전환 검토

## 11. 앱 이름 후보 (확정 필요)

"CamScanner"는 상표이므로 그대로 사용할 수 없습니다. 후보:

- 심플스캔 (SimpleScan)
- 스냅독 (SnapDoc)
- 클린스캔 (CleanScan)
- 문서똑 (DocDdok)
